# OriginalRoot Phase 9: evidence-backed batch records

## Goal

Let growers attach supporting images to a harvest offer, let operators review and attribute decisions, and show only approved evidence on the linked public batch passport.

## Included

- Growers can upload JPEG, PNG, or WebP images up to 2 MB for a harvest offer owned by their account. The offer must be pending review or published.
- Uploaded files are stored in the local data directory, outside the static web root. Filenames are generated by the server; uploads are not served as HTML or SVG.
- Each submission stores its batch link, category, caption, MIME type, byte size, SHA-256 checksum, submit time, and review status.
- Growers can see their own submissions and review notes. Operators can see all submissions, inspect the image, approve it for the passport, decline it, or withdraw a prior approval.
- Decisions and grower submissions are appended to an evidence history and operator audit log.
- The public batch passport lists only approved evidence for a published batch. Public metadata identifies the reviewer as OriginalRoot operations, not as an independent certifier.
- SQLite tables are created additively for existing local installations. Docker stores the image files under `/data/evidence` in the existing persistent data volume.

## Local workflow

1. Start the Docker application and sign in to a grower account.
2. Submit a harvest offer, or select one of your already published offers.
3. In **Batch evidence**, choose the offer, select a category, add a short factual note, and upload an image.
4. Sign in as an operator and open **Evidence review**. Compare the image with the stated claim and record an approval or a specific reason for declining it.
5. Only approved evidence for a published batch appears in its public Farm Passport. Growers can review the status and operator note in their account.

## API routes

- `GET|POST /api/grower/evidence`
- `GET /api/operator/evidence`
- `POST /api/operator/evidence/{evidence_id}/decision`
- `GET /api/evidence/{evidence_id}/file`
- `GET /api/harvest-listings/{listing_id}/passport` now includes approved evidence metadata.

Evidence file access is public only after approval and only while its batch is published. Before that, the grower who submitted it and signed-in operators can view it. The API checks the stored file size and checksum before serving it.

## Boundaries

An image and an operator review are supporting records. They do not independently prove farm ownership, crop origin, grade, organic status, food safety, or the truth of a claim. The software cannot perform an in-person inspection. Remove location metadata before upload. Do not upload identity documents, customer information, payment information, or unrelated private material. An approved image is visible to anyone who can access the public batch passport.

Evidence is kept in the same local Docker volume as the SQLite database. Removing that volume deletes both the records and files. This phase does not add cloud storage, image redaction, automatic expiry/deletion, external certification, or internet deployment. Keep the service bound to loopback and use only appropriate pilot materials until a retention and privacy process is in place.
